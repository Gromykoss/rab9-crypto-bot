# Proposal: wallet-watch (фича P1)

## Проблема
Слежение за движением КОНКРЕТНЫХ кошельков умерло 11.10 (alerts.py удалён при демонтаже, шли через удалённого бота). Топ-накопитель 4EMfevH3 (4.49% саплая) продолжает докупать — движения видны только в кроне-снапшоте 4 раза/день, с запозданием.

## Зачем сейчас
PumpPortal умеет `subscribeAccountTrade` — пуш движений кошелька на уровне блоков, бесплатно, тот же WS-коннект что у фичи 1. Продажа топ-кита = момент истины, нельзя пропустить.

## Скоуп
- `data/wallet_watch.json` — расширяемый список адресов (старт: 4EMfevH3Ysbw6S5CATzsgBJbutLV62MtrJJmo3F9zaQ9)
- `pumpportal_listener.py`: вторая подписка в той же WS-сессии `subscribeAccountTrade` (keys = список); события `txType buy/sell` → sink `type=wallet` (немедленно в дайджест)
- Дедуп 24ч НЕ применяется к wallet-событиям (движения одного кошелька — легитимные повторы)
- Добавление/удаление кошельков — правкой файла, без правок кода

## Вне скоупа
- Полные отчёты по кошелькам (wallet_intel-профили) — вручную через /analyze
- Автодобавление кошельков в watch — вручную владельцем

## Критерий готовности
1. WS-сессия держит обе подписки (migration + accountTrade), обои ack'и логируются
2. Тест: событие txType=sell watched-кошелька → sink-запись type=wallet с полем txType/solAmount/tokenAmount
3. Дедуп не задействован (негатив-тест: записи дедупа не создаются)
4. Список кошельков перечитывается при переподключении WS (файл → без рестарта процесса)
5. Suite зелёный, SDG закрыты SHA

## Границы
- Читает: data/wallet_watch.json; пишет: sink (общий, O_APPEND — конкурентность с analyzer безопасна)
- Не трогает: пайплайн, operators, X API
