# Методика отбора токенов — вход PumpPortal (v0.1 FROZEN, с правками Researcher 11.10)

> Контекст: замена умершего MSF-входа. Пуш = PumpPortal WS `subscribeMigration`
> (токен прошёл bonding curve → PumpSwap). Задача методики: из потока миграций
> отобрать единицы, достойные полного AI-анализа и доставки владельцу, не заваливая
> его потоком. Всё ниже — существующие наработки стэка RAB9 + новые пороги.

## Воронка (каждый слой отсекает, следующий дороже)

### Слой 0 — вход
- Только `subscribeMigration` (не creation, не trade): первый скам-фильтр —
  токен пережил bonding curve.
- Дедуп 24ч (`msf_dedupe`): повторный адрес не анализируется, независимо от входа.

### Слой 1 — мгновенные фильтры (DexScreener, бесплатно, миллисекунды)
- КАСКАД t=0 (правка Researcher 11.10: градуация при ~85 SOL → пул ~3-17K$, MC ~9-75K$,
  жёсткие пороги на t=0 отрезали бы почти весь вход):
  t=0 — мягкий чек (лог + флаг, НЕ дроп) → перепроверка через 15-30 мин →
  пороги включаются: ликвидность ≥ порога (конфиг, стартовое значение ~$15K),
  MC в окне конфига (старт ~$50K–5M); MC > 5M → escalate-строка владельцу
- Токен, устойчивый до второй проверки (не умер, ликвидность на месте) — кандидат слоя 5
- Все пороги — конфиг-переменные, не константы в коде

### Слой 2 — risk-профиль мигранта (правка Researcher 11.10, п.1)
- Мигрант торгует на стандартном контракте PumpSwap AMM, LP сожжён (liquidity locked,
  LP-руг невозможен) → honeypot-чек в моменте почти бесполезен
- honeypot/rugcheck → ИНФОРМАЦИОННАЯ строка вердикта, НЕ hard-гейт (DROP остаётся
  только для подтверждённого scam по семантике operators SAFETY_GATES)
- Взамен: распределение саплая на входе — концентрация топ-10 холдеров в конфиг-порог
  (старт >30% → флаг в вердикте)
- НЕ проверено Researcher: LP-burn по одному источнику — учитывать как признак, не аксиому

### Слой 3 — умные детекторы (существующие)
- `cabal_detector`: связанные кошельки / скоординированная активность →
  CABAL_EXPLOSION / KOL_ACTIVATION алерты (алерт ДО основного анализа — быстрый ранний сигнал)
- `wallet_intel`: KABAL-кошельки (P≥80%) в топ-20 мейкерах → эскалация приоритета
- `phase_detector`: фаза токена; DEAD → INCONCLUSIVE, не полный анализ

### Слой 4 — коммьюнити-сентимент (наработка burnie_sentiment_tracker)
- Сейчас трекер следит за X-аккаунтом BURNIE: rug/scam/dump-тональность,
  пишет в `data/community_sentiment.jsonl` (последняя тональность входит в анализ ядра).
- Обобщение на новые токены: у токена миграции есть X/соц-ссылки из DexScreener
  profile → если аккаунт найден: разовый x_search по `(token/ticker) AND
  (rug OR scam OR dump OR warning OR abandoned OR dead OR "exit liquidity")`,
  отрицательная тональность ≥ порога → понижение приоритета / флаг.
- Нет аккаунта / нет данных → нейтрально, НЕ блокирует (токены миграции молодые,
  отсутствие соцсетей — минус в скоринг, не отсечка).
- ПРАВКА Researcher 11.10 (п.7, Social-Presence Effect): живой аккаунт с активностью =
  ПЛЮС к приоритету очереди анализа (не только негативный фильтр).

### Слой 4b — петля исходов (правка Researcher 11.10, п.4 — главная)
- Каждый вердикт PASS/FLAG через 24ч получает ИСХОД: 2x / умер / флэт → jsonl
  (data/verdict_outcomes.jsonl).
- Цель: через 2-3 недели собственных данных — эмпирическая калибровка всех порогов
  (какой отсекает руги, какой срезает победителей). Методика учится, не догмат.
- Будущее (не v0.1): hazard-rate модель выживания на накопленных исходах (п.8).
- Ограничение: X API (xurl, read-only) — лимиты; проверка тональности только для
  токенов, прошедших слои 1-3 (единицы, не тысячи).

### Слой 5 — полный AI-анализ (дорого, только для выживших)
- Rate cap: ≤ 15-20 полных анализов/час, приоритет = ликвидность + приоритет от
  cabal/wallet_intel (KABAL-эскалации вне очереди); переполнение → дайджест-строка.
- `meme_score` 115 pts / 7-pillar v3.0 + `chart_analysis` + `onchain_check` +
  radar_x/radar_gh → DeepSeek (maker) → `loop_verifier` (Grok, checker, MoA),
  REJECT default, FLAG дважды → REJECT.

### Слой 6 — доставка
- Полный отчёт владельцу: только вердикты, прошедшие verifier (PASS/FLAG),
  формат: вердикт + расшифровка метрик, итог СЛЕДИТЬ/НАБЛЮДАТЬ/НЕ СЛЕДИТЬ.
- REJECT/SKIP: одной строкой или пачкой в дайджесте (раз в N часов), не поштучно.
- Доставка: в чат Cryptanalyst через RAB9-профиль (боты удалены, Песочницы нет).

## Открытые вопросы к Researcher
1. Реальная частота миграций pump.fun за сутки (нужна статистика — подписка на 24-48ч
   или публичные данные): от неё зависит, хватает ли rate cap 15-20/ч.
2. Порог ликвидности $20K: адекватен для токенов сразу после миграции (типичный
   размер начального пула PumpSwap?) — проверить эмпирику.
3. Сентимент-слой: достаточно ли разового x_search по негативным ключевым словам,
   или нужен лёгкий скоринг тональности (без LLM, по ключевым словам)?
4. Порядок слоёв 2-4: что дешевле/информативнее раньше — safety или cabal?
5. Приоритезация rate cap: ликвидность vs KABAL-эскалация — согласована ли формула?
