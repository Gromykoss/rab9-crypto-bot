# CONTEXT.md — язык проекта RAB9 (BURNIE)

> Шаг 1 CDD, создан 2026-10-11 для фичи pumpportal-ingress. Не перезаписывать — только diff + согласование.

## Сущности

| Сущность | Смысл | Идентификатор |
|----------|-------|---------------|
| Сигнальный вход | источник адресов Solana-токенов, триггерящий анализ | канал-модуль (pumpportal_listener / Dexscreener-сканеры) |
| MSF-сигнал | событие «найден адрес токена» на входе | `{chain:"solana", address}` |
| Ingress HTTP | единственная точка приёма сигналов ядром | POST `:8089/msf-signal` + заголовок `X-RAB9-SECRET` |
| Ядро анализа | rab9_bot.py: приём → cabal_detector → DexScreener → wallet_intel → DeepSeek → loop_verifier → Telegram | процесс systemd `rab9-crypto-hermes` |
| Миграция | токен pump.fun прошёл bonding curve и создал пул на PumpSwap | событие `subscribeMigration` (PumpPortal WS) |
| Дедуп | защита от повторного анализа того же адреса в 24ч | `msf_dedupe.json` |
| Песочница | целевой чат доставки сигналов | Telegram `-1003979753733` |

## Связи

- Сигнальный вход → Ingress HTTP (1:N): любой вход шлёт только в `/msf-signal`, других дверей нет.
- Ingress HTTP → Ядро анализа (1:1): валидный сигнал запускает один полный прогон анализа.
- Дедуп → Ядро анализа: повторный адрес в 24ч не запускает новый прогон.

## Глоссарий

- **Вход** = источник адресов (пуш или поллинг). НЕ «источник данных» вообще.
- **Миграция** = переход токена на PumpSwap после bonding curve. НЕ «создание токена» (creation — отдельная подписка, шум).
- **Вывод MSF-входа из эксплуатации** = решение владельца 11.10: группа «Мемы» умерла, бот @msf_rab_bot удаляется. msf_listener.py и юнит msf-listener.service подлежат демонтажу в рамках фичи (systemd-юнит — руками владельца, я только код + конфиг). История остаётся в git.
- **REJECT default** = при неопределённости верификатора сигнал не доставляется.

## Инварианты языка

- «Сигнал» — только валидный Solana-адрес, дошедший до Ingress HTTP; события WS без адреса сигналом не являются.
- Один токен = один анализ в 24ч, независимо от числа входов.

## Жизненные циклы

- Сигнал: обнаружен (вход) → принят (HTTP 200) → проанализирован (PASS/FLAG/FAIL/REJECT) → доставлен или подавлен.
- Вход: активен / отключён владельцем (демонтаж: код удалён, история в git).
