# ADR-0001: Standalone-анализатор вместо Telegram-бот-ядра

Дата: 2026-10-11 · Статус: принято (владелец) · Фича: standalone-analyzer

## Контекст

Ядро RAB9 исторически = python-telegram-bot процесс: боты были одновременно UI (ручные команды), доставкой (Песочница) и хостом HTTP-ingress. Владелец удалил обоих ботов и Песочницу (11.10): без токена ядро не может даже подняться при следующем рестарте, доставка мертва.

## Решение

Выделить HTTP-ingress + аналитический пайплайн в самостоятельный процесс без Telegram-зависимостей. Вывод — в локальный sink (`data/analyses_out/`); доставку человеку выполняет RAB9-агент (Hermes-профиль) в чат Cryptanalyst, через накопительный дайджест (качество выше количества — прямая установка владельца). Ручной анализ — через агента и POST `/analyze`.

## Рассмотренные альтернативы

1. **Новый Telegram-бот (новый токен от BotFather)** — отвергнуто владельцем: боты удалены сознательно, возврат к той же архитектуре не решает проблему «доставка = отдельный SPOF с токеном», интерактивность была минимальной.
2. **Оставить ядро и заглушить Telegram-слой (dummy Application)** — отвергнуто: zombie-зависимость от python-telegram-bot, unreachable-код handlers, усложнение поддержки; не проходит простоту.
3. **Крон-скрипт вместо сервиса** — отвергнуто: разрыв пуш-семантики ingress (HTTP-сервер должен жить постоянно), lost in-flight анализ при рестартах крона.

## Последствия

- (+) Нет зависимости от Telegram-токенов вообще; пайплайн и ingress живут в одном простом процессе.
- (+) Доставка управляема агентом: дайджест, фильтр качества, формат под правила отчётов.
- (−) Теряется мгновенный пуш человеку — компенсировано дайджестом 4ч и ручным анализом через агента.
- (−) Sink = новый контракт, который нужно мониторить (рост файлов, ротация).
- Обратный путь: тяжёлый (демонтаж Telegram-модулей ядра) — осознанно, это и есть причина ADR.
